# Signal Canvas 整站 UI  redesign 设计文档

- 日期：2026-11-09
- 产品：ML Fieldbook · 机器学习实验志
- 状态：用户已选择 A · Signal Canvas；待本设计文档确认后实施
- 范围：现有网页的视觉、信息层级、排版、注释、响应式与动效统一
- 非范围：新增课程、修改学习算法、改造后端数据合同、伪造学习指标

## 1. 意图与原因

当前产品已经有完整的学习闭环、详细的九章教学内容、真实交互实验和具有辨识度的 3D 开始页，但开始页与学习应用之间存在视觉断裂。学习应用内部又有较多相似卡片、英文微标签、小号辅助文字和并列信息，导致“现在最该做什么”不够突出。

本次 redesign 的目的不是继续叠加特效，而是把现有能力组织成一个清晰、现代、可长时间使用的学习空间：第一眼有鲜明品牌和学习反馈，进入正文后安静、可读，在实验和证据反馈时恢复必要的视觉强度。

目标用户仍以机器学习初学者为主。内容保持“图形直觉＋必要数学推导＋代码实验”，每次学习围绕一个具体问题进行。视觉高级感应来自原创的信息组织、图形表达、排版比例和连续转场，而不是装饰数量。

## 2. 目标、非目标与反目标

### 2.1 目标

1. 建立从 Welcome 到所有学习路由的统一 Signal Canvas 视觉语言。
2. 每个页面在首屏内清楚表达唯一主任务、当前进度和下一步。
3. 让正文、公式、代码、题目和注释适合持续阅读，减少小字与边角信息。
4. 用一条有语义的“学习信号轨迹”连接理解、实验、练习、反馈与证据。
5. 在桌面、平板、手机和减少动态模式下保留同样的信息与核心功能。
6. 保持现有真实学习记录、统计口径、作答与诊断行为不变。

### 2.2 非目标

- 不增加新课程、新题库、新账户体系或社交功能。
- 不重写 Three.js 开始页场景，不为了整站动效引入新的大型动画依赖。
- 不修改 FastAPI、SQLite、API 字段、掌握状态或复习规则。
- 不把所有页面统一成同一种卡片网格。
- 不制作暗色阅读模式开关、紧凑密度开关等额外偏好功能。

### 2.3 反目标

以下结果即使视觉上新鲜，也视为失败：

- 长文阅读中存在持续漂浮、闪烁、水流或强光干扰。
- 用玻璃模糊、渐变或 3D 掩盖信息层级问题。
- 把关键解释藏进 hover tooltip 或不可发现的折叠区。
- 为配合设计而显示虚假的完成度、掌握率、学习时长或活动。
- 仅缩小桌面布局来适配手机，或引入横向页面滚动。
- 牺牲键盘、焦点、对比度、减少动态和 WebGL 降级体验。

## 3. 已考虑的方向

### A. Signal Canvas（已选择）

延续紫色、荧光绿、墨色与明亮画布，以编辑式排版、学习轨迹和精密数据图形形成识别度。Welcome 保留沉浸感；正文保持明亮安静；实验与模型观察区可以局部使用深色。兼顾视觉冲击、阅读与现有实现衔接。

### B. Living Textbook

将整站做成未来教材，以杂志跨页、图解和边注为主。阅读最纯粹，但科技感较弱，与当前 3D Welcome 反差更大。本设计吸收其教材式注释和稳定阅读列，不采用其整体风格。

### C. Night Lab

将暗色、玻璃和发光数据延伸到全站，第一眼冲击最强，但长文阅读、视觉疲劳、移动端性能和可访问性风险更高。本设计只把深色用于局部实验和模型观察区，不采用全站暗色。

选择 A 的原因：它最能同时满足用户提出的“前沿高级、布局清晰、适合学习”，且不需要抛弃已经完成的开始页与学习功能。

## 4. 核心视觉概念

### 4.1 一条学习信号轨迹

轨迹是信息组件，不是背景装饰。它用于：

- 今日学习：连接理解、实验、练习和反思，显示真实步骤状态。
- 学习路径：连接线性回归、过拟合和正则化，表达先修关系。
- 概念学习：作为本节目录和当前阅读位置。
- 练习反馈：连接作答、误解反馈和下一步补救。
- 进度与日志：把学习状态关联到真实证据事件。

轨迹只使用已有 API 数据；无数据时显示“尚未记录”或“证据不足”，不以动画填充假进度。

### 4.2 明亮学习画布与局部深色实验场

- 主画布继续使用低噪声的浅灰纸张色。
- 墨色承担正文和主要导航，紫色用于当前位置、关键动作和模型信号。
- 荧光绿用于当前步骤、完成与关键反馈，不大面积铺满正文。
- 深色仅用于 Welcome、实验观察区和需要突出模型关系的局部面板。
- 玻璃材质只用于确实叠加在图形上方的注释或浮层，不作为所有卡片的默认样式。

### 4.3 少卡片、强分区

优先使用标题、留白、细分隔线和轨迹组织内容。只有需要形成独立操作边界的内容才使用卡片，例如完成标准、实验控制台、作答区。页面不再用多个同权重卡片争夺注意力。

## 5. 全局框架与布局

### 5.1 桌面框架

- 保留固定横向主导航，不恢复传统侧栏。
- 顶栏约为 72–80px，由品牌、六个主导航、搜索和今日记录组成。
- 中文导航为主要标签，约 15px；英文微标签不再承担导航含义。
- 搜索保留 Ctrl/Cmd+K；今日时间只作辅助，不抢过主行动。
- 主内容最大宽度约 1440px，采用 12 列网格和稳定页面边距。
- 页面标题、主任务和第一层操作在同一阅读轴线上，避免信息散落四角。

### 5.2 移动框架

- 保留简洁移动顶栏和底部主导航，功能入口不减少。
- 移动底栏文字目标为 13–14px，触控区域至少 44×44px。
- 多列内容按任务顺序重排为单列，而不是整体缩小。
- 桌面右侧注释和目录进入正文中的明确位置；必要内容默认可见，次要内容才折叠。
- 页面边距约 18–24px，长公式只在自身容器内滚动。

### 5.3 排版尺度

建立有限、可复用的排版令牌，不再为单个组件临时发明小字号：

| 用途 | 目标尺寸 |
| --- | --- |
| Welcome 展示标题 | 保留现有响应式大标题体系 |
| 应用页面主标题 | 桌面 48–64px；手机 34–42px |
| 节标题 | 24–32px |
| 卡片或模块标题 | 18–22px |
| 长文正文 | 17–18px，行高约 1.8 |
| 普通界面正文 | 16–17px |
| 功能性辅助文字与注释 | 14–15px |
| 代码 | 14–15px，长文代码可按容器调整但不低于 13px |
| 导航与按钮 | 15–17px |
| 纯装饰编号 | 可减少使用；不得替代功能标签 |

原则上清除现有 10–13px 的功能文字。图表刻度如果确实受空间限制，可使用较小字号，但必须提供可访问名称、直接标注或文本数据替代，不成为唯一信息来源。

## 6. 注释系统

全站只保留三种有明确语义的注释：

1. **注 / NOTE**：解释符号、前提、实验条件和次要背景。
2. **常见误解**：紧跟对应内容，指出错误直觉及修正方向。
3. **来源**：沿用现有概念、分类或词条级阅读列表，并在适用模块附近展示；没有逐条来源映射时，不暗示某个公式或结论已有独立的 claim-level 出处。本阶段不新增来源核验或内容建模工作。

桌面宽屏可把短注释放到阅读列右侧，但正文与注释的从属关系必须清晰。窄屏把注释放回相关段落之后。关键知识、题目要求和操作错误不能依赖 hover 才可见。折叠只用于次要补充，并有明确的展开状态和键盘支持。

## 7. 页面设计

### 7.1 Welcome `/`

- 保留“从数据，到理解。”、回归场、水流、玻璃标注和进入过渡。
- 只统一品牌、按钮和进入后的视觉衔接，不再无目的增加场景特效。
- Welcome 的轨迹语义在 Today 中得到延续，使用户感到进入同一学习空间，而不是跳到另一个产品。

### 7.2 今日学习 `/today`

首屏顺序：

1. 页面命题“今天，只把一个问题想清楚。”与当天主题。
2. 唯一主 CTA“继续学习／开始本节”。
3. 理解、实验、练习、反思的今日信号轨迹。
4. 当前任务与完成标准组成的主工作区。

今日分钟、待复习、完成小节整合到完成标准或第二层摘要中，不与主任务并列争夺注意力。学习路径、本周节奏和最近活动放在第二屏。首次诊断邀请保留，但作为有明确动作的横向前置引导，不覆盖今日主路径。

### 7.3 学习路径 `/learn`

- 将三个相似概念卡片改为三段大型章节带。
- 每章包含大号章节号、中英文标题、核心问题、独立概念图、真实进度和进入动作。
- 章节之间用先修轨迹连接，清楚表达“预测 → 泛化 → 约束”。
- “先看见、再推导、后验证”保留为简洁学习说明，不与章节主体竞争。
- 概念库入口保留，但降为路径结束后的辅助动作。

### 7.4 概念学习 `/learn/:slug`

- 页首交代所属章节、本节问题和当前所处步骤。
- 桌面采用“正文 7–8 列＋本节目录/注释 3–4 列”；正文有效宽度约 720–800px。
- 教学块、手算例题、代码、误解和自测按学习顺序展开，减少嵌套卡片。
- 本节导航在桌面可粘性定位，只标出真实当前位置；移动端回到正文流。
- 深链 `#section-*`、实验锚点、公式滚动、代码复制和完成记录行为保持不变。
- 自测必须仍是清楚的主任务，而不是页面底部的小字附属区。反思复用现有按日期记录的 Journal：可以提供明显的“记录今日反思”入口，但本阶段不新增概念级反思编辑器或持久化字段。

### 7.5 概念库 `/foundations` 与词条详情

- 搜索是页面主动作，使用明显的搜索框与可读筛选器。
- 分类筛选显示选中状态和结果数量；搜索无结果时给出可恢复动作。
- 列表优先采用清晰的词条行或宽松双栏，不以大量相同小卡片压缩定义。
- 详情页与概念学习共享正文、公式、代码、注释和来源排版。
- 相关词条、前后翻页和读本入口保持可用。

### 7.6 练习 `/practice`

- 默认聚焦当前一道题：题目与选项为主体，置信度和提交构成明确操作顺序。
- 提示以注释形式出现；提交前不泄露答案。
- 提交后，正误、误解解释和补救动作进入同一反馈区，而不是另开无关面板。
- 练习队列、进度和统计退居辅助位置。
- 按钮加载、防重复提交、失败恢复和键盘行为保持不变。

### 7.7 进度 `/progress`

- 首屏回答“我现在能做什么、还缺什么证据、下一步是什么”。
- 使用证据状态、任务类型和跨会话信息，不制造精确掌握率。
- 图表有单位、文字结论和非颜色编码；空数据明确显示证据不足。
- 真实活动、作答和复习记录是状态来源，视觉 redesign 不重算这些状态。

### 7.8 日志 `/journal`

- 以清晰时间线组织自动事件和手动反思。
- 日期、事件类型和反思内容形成稳定的阅读层级。
- 编辑器拥有足够大的正文区域与明确保存状态，不把保存提示放在难以发现的角落。
- 不为了视觉统一而把日志改成统计卡片页。

### 7.9 起点诊断 `/diagnostic`

- 延续聚焦作答的版式，使用统一标题、正文、置信度和反馈组件。
- 诊断过程中减少无关导航干扰；结果页清楚表达证据、局限与推荐入口。
- 保持 intro → 8 题 → 结果、幂等提交和不污染概念练习证据的逻辑。

## 8. 动效与交互反馈

动效只承担四种职责：解释来源与去向、表达参数与结果关系、反馈操作状态、保持路由空间连续性。

- 路由和主要区域转场以约 240–420ms 的透明度、位移和轨迹绘制为主。
- 今日步骤推进、章节进入、作答反馈和保存状态可以有明确的一次性反馈。
- 图表只在数据变化时过渡，不在阅读时循环吸引注意力。
- 不在长文正文中增加持续水流、漂浮或视差。
- 保留 Welcome 的 reduced-motion 静态帧；应用内减少动态时取消非必要位移和循环动画。
- hover 不是获取必要信息的唯一方式；触屏不依赖磁吸或指针光场。

## 9. 实现边界与技术约束

- 沿用 React 19、TypeScript、React Router、TanStack Query、CSS、KaTeX、Lucide 和现有 Three.js。
- 不增加新运行时依赖；优先通过设计令牌、共享组件和 CSS 重构完成。
- 不新增第三套覆盖全站的临时样式层。先梳理 `global.css` 与 `signal.css` 的职责，再按共享令牌、应用框架、页面模块组织改动；`lesson.css` 和 `welcome.css` 保留明确职责。
- 复用现有 API 与 React Query 数据，不为视觉效果创建平行假数据。
- 尽可能通过共享排版、按钮、注释、章节轨迹和页面头部组件减少页面级例外。
- 后端、内容 JSON、数据库和 API 合同原则上不改；如果实施中发现必须变更，应先停止并说明原因。
- 保持现有懒加载、Three.js 分包、WebGL fallback 和资源释放。
- 本目录不是 Git 仓库，因此设计文档可以写入项目，但无法按技能模板进行 Git 提交；不擅自初始化仓库。

## 10. 响应式、可访问性与性能验收

### 10.1 布局验收

- 检查 320、390、768、1024、1440、1920px。
- 核心路由无页面级横向溢出；长公式和代码只在局部容器滚动。
- 检查 200% 缩放、长中文、空数据、加载和错误状态。
- 导航、按钮、筛选、折叠和移动底栏具有至少 44px 的触控目标。

### 10.2 可访问性验收

- 键盘可完成导航、搜索、阅读深链、实验、作答、保存和关闭浮层。
- 焦点样式清楚，弹层打开/关闭时焦点管理正确。
- 正文、辅助文字、按钮和状态满足 WCAG 2.2 AA 对比度。
- 状态不只靠颜色；图表有文本替代。
- `prefers-reduced-motion` 下无信息或功能损失。
- 对主要路由、命令面板和关键反馈状态运行 axe，目标为 0 violations，并辅以人工检查。

### 10.3 功能与性能验收

- 前端生产构建、现有前端测试和后端测试通过。
- 开始、诊断、学习、实验、练习、进度、日志和概念库核心流程无回归。
- 无阻断性控制台错误、死按钮、假进度或答案提前泄露。
- 不引入新的大型动画依赖；Three.js 引擎不回到超过 500kB 的警告状态。
- 浏览器性能结论如实描述测试环境，不把软件渲染 FPS 当作真实用户性能。

## 11. 交付顺序

1. **基础系统：** 色彩、字体、间距、按钮、注释、导航和 12 列网格。
2. **主路径：** Today 与 Learn，验证 Signal Canvas 的核心视觉语言。
3. **深度学习：** Concept、Lesson、Experiment 与 Practice，优先保证长文和作答。
4. **证据与检索：** Foundations、Progress、Journal、Diagnostic。
5. **整站验收：** 路由、响应式、键盘、减少动态、axe、构建与回归测试。

每一阶段只改变表现与信息组织，不借 redesign 名义修改真实学习证据。最终页面是否“眼前一亮”仍需要用户在浏览器中审阅；自动化验收不能替代这一主观判断。

## 12. 留给实施者的决定

以下不会改变产品目标，可由实施者根据现有代码决定：

- 具体 CSS 令牌名称和少量像素级尺寸。
- 共享组件的最小拆分粒度。
- 章节图形是否复用或扩展现有 ConceptArt。
- 在不动数据合同的前提下，各页面 DOM 的最小必要调整。
- 为保持性能而选择的纯 CSS、SVG 或现有 Canvas 实现方式。
